# 계산 방식

모든 숫자는 계산식과 입력값을 함께 남겨, 화면에서 값에 마우스를 올리면 어떻게 나왔는지 보입니다. "예시값"이라고 적힌 기본값은 형식 확인용이니 실제로 잰 값으로 바꾸세요.

## 트래픽
- 페르소나마다 접속 시각·횟수·시간을 무작위로 뽑아 하루를 만들고(시드가 같으면 결과도 같음), 시간대별 RPS와 피크를 구합니다.
- 이벤트 피크 = 평소 피크 × 이벤트 배수.
- 데이터 주고받기(폴링 주기·모아 보내기)가 요청 수를 바꿉니다.
- 1분 단위 기대 곡선(같은 가정의 평균)도 계산해 아래 그래프와 큐 소비자에 씁니다. 하루 양은 무작위 하루와 같게 맞춥니다.
- **일시적 급증(켰을 때):** 무작위 시각(시드 고정)에 정한 시간 동안 부하가 1 → 높이 → 1로 산 모양으로 오르내립니다. 겹쳐도 높이(최대 1.5배)를 넘지 않고, 급증만큼 하루 도착이 늘어납니다. 지금은 1분 곡선(그래프·큐 소비자)에만 들어가고, 서버 대수 계산의 피크 RPS는 바꾸지 않습니다.

## 용량·지연·한계
- 부하는 연결선을 따라 내려갑니다(호출 비율, 읽기·쓰기 구분, 캐시 적중률만큼 DB 읽기 감소 — 기본 0.8, 예시값).
- 필요 대수 = ceil(부하 / (대당 처리량 × 목표 사용률)), 최소·최대 대수로 자름. 대당 처리량은 업계 기준값을 사양·실측으로 보정합니다.
- 주 서버 1대 DB(PostgreSQL·MySQL·MongoDB·SQLite 등)는 쓰기를 주 서버가 모두 받고, 읽기 복제본이 있으면 읽기만 나눕니다.
- DB 연결 수 = Σ 부르는 노드 대수 × 연결 풀(기본 10). 연결 풀러가 있으면 풀러 크기까지만.
- p99는 대기열 모형(Erlang C)으로, 경로 p99는 동기 경로를 따라 더합니다.
- 한계 사용자 = 이벤트 피크에서 "안 됨"이 되기 직전의 사용자 수. 가장 먼저 닿는 노드가 첫 병목입니다.

## 데이터 파이프라인
- **큐 → 소비자:** 처리량 = min(소비자 대수 × 대당 동시 처리, 파티션 수) × 1000 / 처리 ms. 하루를 30초 칸으로 돌며 적체를 쌓고 빼고, 지연 = 적체 / 처리량 + 1건 처리 시간. 고정 대수 소비자는 도착을 설정의 계산 단위(1·5·15·60분, 기본 60분)마다 평균해 씁니다. 하루 평균 도착이 처리량 이상이면 끝없이 쌓입니다.
- **자동 확장 소비자(KEDA처럼):** 1분 단위 곡선으로 하루를 30초 칸으로 돌립니다.
  - 확인 주기(기본 30초, KEDA pollingInterval)마다 필요 대수 = ceil(도착 × 처리 시간 / (대당 동시 처리 × 목표 사용률)), 최소~최대(없으면 파티션 수 / 대당 동시 처리).
  - 새 소비자는 뜨는 시간(기본 30초, **예시값**) 뒤에 처리를 시작하고, 줄일 때는 줄이기 전 기다림(기본 300초, KEDA cooldownPeriod) 동안 필요했던 가장 큰 대수 아래로 내리지 않습니다.
  - 비용은 시간대별 평균 대수, DB 연결 수는 가장 많을 때 대수로 셉니다.
- **주기 배치:** 1회 실행 = 주기 동안 들어온 양 / 처리량(실행 창 안에 끝나야 함), 반영까지 최대 = 주기 + 1회 실행.

## 장애
- **존 하나:** 서버를 존 수에 고르게 나눴다고 보고 ceil(대수 / 존 수)대를 잃습니다. 남은 서버 사용률 = 지금 × 대수 / 남은 대수. 주 서버 1대 DB는 대기 서버로 넘깁니다(60초, 예시값).
- **리전 하나:** 다른 리전 복사본이 없는 노드는 멈추고, 그 노드에 동기로 닿는 화면이 멈춥니다. 복사본으로 넘기는 시간은 같이 받기 60초·대기 900초(예시값), 대기 복사본으로 넘긴 직후 사용률 = 지금 × 대수 / 대기 대수.
- **백업:** RPO = 백업 주기·시점 복구(5분)·리전 복제 지연(5초) 중 짧은 것, RTO = 새 서버 준비(10분) + 데이터 크기 / 되살리는 속도(100MB/초). 괄호 안은 예시값입니다.

## 비용
- 과금 방식별로 셉니다: 대수 × 시간(시간대별 대수), 사용량(요청·연산 시간·스캔량), 월 정액.
- 저장(테이블 저장량), 인터넷 송신, 리전이 다른 노드 사이 전송을 더합니다.
- 리전 복사본: 같이 받기는 같은 대수, 대기는 대기 대수를 그 리전 가격으로 더하고, 데이터 노드는 복사본 저장량과 복제 전송(하루 쓰는 행 × 행 크기 × 30일)을 더합니다.
- 가격이 없는 상품·리전은 0원으로 채우지 않고 "가격 없음"으로 알립니다.

## 판정
- 항목마다 카탈로그의 조건으로 됨·조건부·안 됨·판단 불가를 냅니다. 평소 피크에서 걸리면 안 됨, 이벤트 피크에서만이면 조건부, 값이 없으면 판단 불가입니다.
- 노드에 거는 공통 규칙: 사용률 100% 초과는 안 됨, 큐 지연이 허용을 넘거나 배치가 실행 창을 넘으면 평소 안 됨·이벤트 조건부.
- 장애 목표를 정하면: 장애로 화면이 멈추면 안 됨, 반영만 늦으면 조건부, 장애 직후 넘치면 조건부(자동 확장이 채움), RTO·RPO를 넘으면 안 됨.
- 판정 순위: 됨 < 조건부 < 판단 불가 < 안 됨.

## 성장
월 성장률 또는 유입 모형으로 달마다 사용자 수를 구해, 노드마다 한계에 닿는 달과 준비를 시작할 달, 달별 비용, 파티션 없는 테이블이 서버 메모리를 넘는 달을 보여 줍니다.

## 법령
개인정보를 두는 노드의 리전·데이터 주체 나라로 한국·일본 법령의 "확인할 조문"을 표시합니다. 법률 검토를 대신하지 않습니다.
