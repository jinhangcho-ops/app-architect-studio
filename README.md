# App Architect Studio

앱을 만들기 전에 구조를 설계하고, 그 구조가 예상 사용자 규모에서 버티는지 미리 계산해 보는 도구입니다. 화면·게이트웨이·서버·큐·DB 같은 블록을 캔버스에 놓고 연결하면, 고른 기술마다 되는지·조건부인지·안 되는지와 더 나은 대안을 알려 줍니다. 트래픽, 필요한 서버 수, 비용, 한계 시점, 확인할 법 조문까지 계산해 설계서(PDF)로 내보냅니다.

![App Architect Studio 첫 화면](docs/screenshot.png)

## 주요 기능

- **구조 설계와 판정**: 레이어별 블록을 연결하고 블록마다 기술(주 항목·보조 항목)을 고르면, 예상 부하에서의 판정·근거·대안이 바로 나옵니다. 카드를 누르면 그 블록의 세부 구성(서버 대수·분배 방식, 테이블, 부품)이 열립니다.
- **페르소나로 트래픽 계산**: 사용자를 사용 패턴별 무리(페르소나)로 나누고, 접속 시간대·나라·접속 횟수·접속 시간으로 하루 트래픽을 5분 단위로 계산합니다. **설정 › 하루 피크**에서 업종(외식·배달, 라이브 게임, 출퇴근, 업무용, 쇼핑, OTT)을 누르면 그 업종의 피크 시각(예: 점심·저녁 두 번)과 페르소나 비율이 한 번에 바뀌고, 그래프의 봉우리를 끌어 시각·폭·비중을 고칠 수 있습니다. 페르소나 비율도 분포의 봉우리를 끌어서 정합니다. 데이터 주고받기 방식(폴링·스트리밍, 최신화 주기, 모아 보내기)도 반영하고, 서비스 성격별 추천값을 제안합니다.
- **용량·비용·한계**: 노드마다 필요한 대수, 사용률, p99 지연, 가용성, 월 비용(가격표 기준)을 계산하고, 사용자가 늘 때 어디가 먼저 막히는지 보여 줍니다. PostgreSQL·MySQL·MongoDB·SQLite 같은 주 서버 1대 DB는 쓰기를 주 서버 1대가 모두 받는 것으로 계산하고(대수를 늘려도 쓰기 한계는 그대로), 읽기 복제본을 붙이면 읽기만 복제본으로 나눕니다. DB 연결 수는 그 DB를 부르는 노드의 대수 × 연결 풀(기본 10)로 계산하고, 연결 풀러가 있으면 풀러 크기까지만 셉니다. 캐시를 함께 부르는 노드는 캐시 적중률(기본 0.8, 예시값)만큼 DB 읽기를 덜 보냅니다. 게이트웨이·로드밸런서도 대당 처리량과 최대 대수로 한계를 계산하고, 어느 노드든 사용률이 100%를 넘으면(늘릴 수 있는 대수를 다 써도 못 받음) 평소·이벤트 피크와 상관없이 "안 됨"으로 판정합니다.
- **데이터 파이프라인**: 큐 노드는 파티션 수와 허용 지연(초)을, 소비자는 대수·평균 처리 시간을 넣으면 하루 시간대마다 적체와 지연을 계산합니다(파티션 수가 소비자 병렬 수의 상한). 주기 배치(실행 주기·실행 창)는 1회 실행 시간과 데이터가 반영되기까지 걸리는 시간을 계산합니다. 평소에 넘치면 안 됨, 이벤트 때만 넘치면 조건부입니다.
- **장애 시나리오**: 노드마다 존 수, 다른 리전 복사본(같이 받기·대기·백업), 백업 주기·시점 복구·되살리는 속도를 넣으면 세 가지를 계산합니다. 존 하나가 멈출 때 남는 서버와 그 사용률, 리전 하나가 멈출 때 멈추는 노드·화면과 넘기는 시간(RTO), 백업에서 되살리는 시간과 잃는 데이터(RPO)입니다. 설정의 "장애 목표"에서 견딜 장애와 목표 RTO·RPO를 정하면 판정에 넣습니다. 화면이 멈추면 안 됨, 반영만 늦어지면 조건부, 목표를 넘으면 안 됨입니다. 넘기는 시간·복제 지연·되살리는 속도의 기본값은 예시값이고, 리전 복사본의 비용은 아직 세지 않습니다.
- **성장과 유입**: 월 성장률, 또는 유입 모형(광고·검색 같은 바깥 유입과 입소문, 페르소나 단계 이동)으로 몇 개월째에 한계에 닿는지, 언제 준비를 시작해야 하는지 계산합니다.
- **테이블과 저장량**: 테이블·컬럼·인덱스 명세로 행 크기와 보관 기간 저장량을 계산하고, SQLite로 직접 실험해 볼 수 있습니다.
- **와이어프레임**: 화면 블록 안에서 데스크톱·태블릿·모바일 화면을 끌어 놓기로 그리고(도형·색 포함), 두 기기를 나란히 볼 수 있습니다. 기존 HTML 파일을 그대로 그려 가져올 수 있고, 버튼에 붙인 API 호출이 연결선과 부하 계산으로 이어집니다. PNG로 저장할 수 있습니다.
- **법령 확인**: 개인정보를 다루는 노드에 한국·일본 법령의 "확인할 조문"을 표시합니다 (법률 검토를 대신하지 않습니다).
- **설계서 PDF**: 판정 근거, 한계·비용, 최선 조합, 화면 설계, 조문, 출처를 A4 설계서로 내보냅니다.
- **저장**: 자동 저장(시점 10개)과 직접 저장(Ctrl+S, 20개), 데스크톱 앱에서는 프로젝트 폴더에 시점 파일을 남겨 강제로 닫혀도 복구할 수 있습니다.

## 설치 (Windows)

1. [Releases](https://github.com/jinhangcho-ops/app-architect-studio/releases)에서 최신 `App-Architect-Studio-Setup-<버전>.exe`를 받습니다.
2. 실행하면 설치 창이 열립니다.
   - 설치 위치를 고릅니다 (기본: `C:\Users\<이름>\AppData\Local\Programs\App Architect Studio`).
   - 마지막 화면에서 **바탕화면에 바로가기 만들기**를 켜거나 끕니다.
3. 시작 메뉴나 바탕화면 바로가기로 실행합니다. 지울 때는 Windows **설정 › 앱**에서 "App Architect Studio"를 제거합니다.

> 설치 파일은 아직 코드 서명이 없어서, 처음 실행할 때 "Windows의 PC 보호" 창이 뜰 수 있습니다. **추가 정보 › 실행**을 누르세요.

> **받은 설치 파일 확인 (권장):** Releases에는 설치 파일과 같은 이름의 `.sha256` 파일(설치 파일의 지문)이 함께 있습니다. 둘을 같은 폴더에 받은 뒤, 그 폴더에서 PowerShell을 열고 아래 한 줄을 실행하세요. 버전 숫자는 받은 파일에 맞게 바꿉니다.
>
> ```powershell
> $f = "App-Architect-Studio-Setup-1.0.0.exe"; if ((Get-FileHash $f).Hash -eq (Get-Content "$f.sha256").Split(' ')[0]) { "일치: 올린 파일 그대로입니다" } else { "다름: 설치하지 말고 다시 받으세요" }
> ```
>
> "다름"이 나오면 받는 도중 파일이 깨졌거나 누군가 바꾼 것입니다. 이 지문은 같은 Releases 페이지에서 받으므로, Releases 자체가 바뀌는 경우까지 막지는 못합니다.

> **앱 파일 변조 검사:** 앱 코드 묶음(`resources/app.asar`)의 지문(SHA-256)이 실행 파일에 들어 있어, 실행할 때마다 Electron이 대조합니다. 한 바이트라도 바뀌었거나 묶음 대신 다른 코드 폴더를 넣으면 앱이 열리지 않습니다. **설치 후 앱이 바로 꺼지면 앱 파일이 손상되거나 바뀐 것이니 최신 설치 파일로 다시 설치하세요.** 코드 서명이 없는 동안에는 실행 파일 자체를 고치는 공격까지는 막지 못합니다.

브라우저에서 바로 써 보려면 아래 [개발](#개발)의 `npm run dev`를 쓰면 됩니다.

## 단축키

| 키 | 동작 |
|---|---|
| Ctrl+S | 저장 (저장 기록에 시점을 남김, 최대 20개) |
| Ctrl+Shift+S | 파일로 내보내기 (JSON) |
| Ctrl+O | 파일 열기 |
| Ctrl+Z / Ctrl+Y | 되돌리기 / 다시 하기 |
| Ctrl+F | 노드·항목·테이블·컬럼 찾기 |
| Ctrl+C / Ctrl+V | 노드 복사 / 붙여넣기 (전체 구조에서) |
| Esc | 설계서 닫기 → 세부 구성에서 나오기 → 선택 해제 |

자동 저장은 고칠 때마다 최신 시점을 덮어쓰고, 간격(기본 10분, **저장 기록**에서 변경)마다 새 시점을 만듭니다(최대 10개). 강제로 닫혀도 다시 열면 복구를 제안합니다. 브라우저 저장소가 꽉 차면 오래된 시점부터 지우고, 그래도 못 쓰면 알려 줍니다.

위쪽의 **설계도 / 설정**으로 화면을 바꿉니다. 사용자 수·페르소나·하루 피크·행동·데이터 주고받기·성장·비용 기준 같은 입력값은 **설정**에 모여 있고, 불러온 뒤 바꾼 항목 수를 노란 숫자로 보여 주며 한 번에 되돌릴 수 있습니다. 설계도 위쪽 줄의 패널 단추로 아래 그래프·오른쪽 결과를 접을 수 있고, **다이어그램만**을 누르면 둘을 한 번에 접습니다.

## 개발

Node 24가 필요합니다.

```bash
npm install
npx install-electron   # 데스크톱 실행용 Electron 런타임 받기 (한 번만)
npm run dev            # 브라우저에서 개발 화면 (http://localhost:5173)
npm test               # 테스트
npm run judge -- examples/phase3.json   # 명령줄에서 예시 프로젝트 계산
npm run desktop        # 데스크톱 앱으로 실행
npm run installer      # release/ 폴더에 설치 파일 만들기
```

새 버전을 배포하려면 `package.json`의 `version`을 올리고 같은 이름의 태그(예: `v1.0.1`)를 올립니다. GitHub Actions가 테스트를 돌린 뒤 Release를 초안으로 만들어 설치 파일과 지문(`.sha256`)을 올리고, 파일이 모두 올라가면 공개합니다.
